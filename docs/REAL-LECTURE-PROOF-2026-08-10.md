## Findings (severity-ordered)

### 1. MAJOR — This lecture's yt-dlp auto-captions are un-deduplicated "rolling" YouTube captions, producing a visibly stuttering transcript pane (F-09)

`captions.json` for this run contains 612 raw segments where each cue is a growing/overlapping window of the previous one (YouTube's rolling auto-caption style), e.g. `[21.99] "Okay, CPAP is typically the term that is"` → `[22.00] "Okay, CPAP is typically the term that is used if this is non-invasive"` → `[25.19] "used if this is non-invasive"`. `captionParse.ts`'s cue-block parser does no cross-cue deduplication. This is **not a regression** — the 2026-08-08 proof's `captions.json` (same parser, different video) is clean, non-overlapping text, confirming this is a per-video YouTube caption-track-format difference. It affects the study view's transcript pane directly (a real learner would see the duplication), the LLM's own chunk prompt, and is the proximate reason the committed verifier's naive concatenation produces a large false-positive-looking violation count.
**Repro:** `docs/proof-evidence-2026-08-10/captions.json` segments 0–20; see FINDINGS.md F-09 for the full comparison against the clean 2026-08-08 caption file.
**Fix direction:** a rolling-caption reconstruction/dedup pass in `captionParse.ts` or `ytdlp.ts` — out of this plan's scope (adversarial verification, not pipeline engineering).

### 2. MAJOR — 10 of 18 units carry anchor timestamps that drift up to ~282 seconds from where the quote is actually spoken (F-10)

Every one of the 32 anchor-verifier violations was manually located in the real transcript. The content is genuinely spoken in every case — this is not hallucination — but for 10 of 18 units, the claimed `t` is meaningfully far from the true position, growing with distance into the lecture: near-zero at t=22 (early material), to ~282s at the latest-covered material. Both clinical safety-tier (DOSAGE) units are affected: `cpap-and-peep-setting-range` (40s drift) and `pressure-support-range` (160s drift, the worst single-anchor case). The numeric values themselves are exact (no rounding/paraphrase) — only the pointer to the source is wrong.
**Repro:** `docs/proof-evidence-2026-08-10/verification/safety-value-audit.md` and `hallucination-audit.md`'s unit table (full drift data for all 10 affected units).
**Fix direction:** not root-caused to a specific code location in this pass — candidates include how the model reads `[mm:ss]`-prefixed chunk-prompt lines when synthesizing a quote spanning several raw (redundant, per F-09) caption lines, or a step in `analysis.ts`'s chunk-to-unit pipeline. Phase 5+ investigation, not this plan's scope.

### 3. MAJOR — A chunk-overlap near-duplicate unit escaped ANLZ-01's anchor-time-aware dedup because its own anchor is one of the F-10-drifted ones (F-11)

`vent-parameters-and-gas-exchange` (claimed anchors t=710/730) and `ventilator-parameter-effects-on-gas-exchange` (correctly anchored, t=430–448) state the same fact — "first two AC parameters affect CO2, last two affect oxygenation" — in near-identical words. `vent-parameters-and-gas-exchange`'s true spoken position is t≈427–448s, the same passage the other unit correctly anchors. Phase 2's anchor-time-aware dedup (ANLZ-01, the fix for the 2026-08-08 proof's Bug 3) did not catch this pair because the surviving duplicate's *claimed* anchor time (710/730) is far outside any proximity window from the other's — even though their *true* positions coincide.
**Repro:** `analysis.json` units `vent-parameters-and-gas-exchange` and `ventilator-parameter-effects-on-gas-exchange`; compare labels/summaries and true positions in `hallucination-audit.md`'s unit #10/#12 rows.
**Fix direction:** likely resolved as a side effect of fixing F-10 (correct anchor times would let the existing anchor-proximity dedup catch this pair) — not investigated further here.

### 4. MINOR — Slide provenance is technically proven wired in but not demonstrably firing in model output this run (F-05)

All 18 units carry `evidence: "transcript"` — none `"slides"` or `"both"` — despite the CDC/NHSN deck being genuinely attached and unconditionally folded into every chunk's prompt (source-confirmed: `analyze.ts:95,113`). The most plausible explanation is the deck's narrower topical scope (VAE surveillance definitions vs. the lecture's broader ventilation-modes teaching, as 04-01's own deck-provenance vetting flagged going in) — but this run cannot empirically distinguish that from a labeling-fidelity gap in the model's own evidence-tagging behavior.
**Repro:** `docs/proof-evidence-2026-08-10/run/clinical-analysis.json` — `grep evidence` shows 18/18 `"transcript"`.

### 5. MINOR — Per-page slide-extraction char counts differ ~3.3% between two measurement runs of the same file (F-04, carried from 04-03)

Same deck, same page count (44), same `emptyPageCount` (0), but per-page character counts differ on every page between 04-01's ephemeral vetting script and the real upload route — likely a `getTextContent()` option difference between the two scripts, not a route-level regression. Does not affect what the analysis actually consumed (the real route's number is authoritative).

### 6. MINOR — Concept-doc attach 403s from the study view until the doc's absolute path is first added in Settings (F-07, carried from 04-04)

`ConceptsDock`'s free-text attach control accepts any path and lets the server reject it with a raw 403 (`isPathAllowedCanonical` requires an exact-match allowlist entry) — the guard itself works as designed, but the two-screen prerequisite (Settings → add path → Save & rescan → back to study view → attach) isn't signposted to a first-time learner.
