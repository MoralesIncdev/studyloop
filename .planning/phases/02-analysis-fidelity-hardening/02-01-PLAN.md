Field shape decision (LOCKED for the whole phase — plan 02-03 must match):

- `enrichment: z.boolean().optional()` on BOTH `ChunkUnitRawSchema` and `AnalysisUnitSchema`. NOT `.default(false)`.
  Reason: `z.infer` on a `.default()` field yields a REQUIRED output property, which would force `enrichment:` into roughly 43 existing `AnalysisUnit` object literals across 14 files (`server/src/lib/review.ts`, `server/src/lib/continuity.ts`, 5 server test files, 6 web test files). `.optional()` mirrors how `evidence`, `overlay`, and `members` already model absence on this same schema. Absent means "not flagged".
- Wire level is the opposite convention and that is deliberate: `CHUNK_V3_JSON_SCHEMA` lists `enrichment: { type: "boolean" }` in `properties` AND `"enrichment"` in `required`, because structured-output json_schema mode wants every property present (same convention `threshold`, `evidence`, `members` already follow at `analysis.ts:772/782/776`).
- Merge output emits `true | undefined`, never `false`: `group.some((g) => g.enrichment === true) ? true : undefined`. Same "don't persist a value nobody actually emitted" rule `mergeEvidence` and `mergeOverlayFields` already follow, so analysis.json gains a key only on flagged units.
- Web mirror: `enrichment?: boolean` on `web/src/lib/types.ts`'s `AnalysisUnit` (optional, matching `evidence?`).
