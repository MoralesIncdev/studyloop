  <behavior>
    - A unit anchor whose quote appears character-for-character in the joined caption text, at a position whose owning segment starts within tolerance of the anchor's t, classifies as exact and is not a violation.
    - A quote that matches only after collapsing runs of whitespace and normalizing case classifies as normalized — reported separately, counted, and not silently folded into exact.
    - A quote that appears nowhere in the caption stream under either comparison classifies as a violation with reason quote-not-found, carrying the unit id, the anchor t, and the quote.
    - A quote that matches but whose owning segment starts more than the tolerance away from the anchor's t classifies as a violation with reason time-drift, carrying both the anchor t and the matched segment's start.
    - Edge quotes carry no timestamp, so they are quote-checked only; a missing edge quote is a violation with the edge's source and target identifying it.
    - Pearls carry a timestamp and no quote, so they are range-checked only: a t beyond the last caption segment's end is a violation with reason timestamp-out-of-range.
    - Tolerance is a parameter with a fifteen-second default, so a future run can tighten it without editing the module.
    - An analysis with zero units, zero edges and zero pearls returns a report with zero checked and zero violations rather than throwing.
    - Captions with an empty segment array produce a violation for every quote rather than a false pass.
    - The report totals are internally consistent: exact plus normalized plus violations equals the number of checks performed.
  </behavior>
  <reversibility rating="reversible">New files only; nothing existing is modified.</reversibility>
  <action>
    Write the tests first in server/test/anchorVerify.test.ts, following the codebase's existing convention of small factory helpers at the top of the file and descriptive describe blocks, using only Vitest and synthetic fixtures — no real project data in the unit tests, no new dependencies.

    Then implement server/src/lib/anchorVerify.ts as pure typed functions with no filesystem access, so the module is trivially testable and the CLI owns all I/O. Provide a function that builds a searchable caption index from a segment array: the joined text plus a mapping from character offset back to the owning segment, so a match position resolves to a real segment start. Provide the classification function that takes the parsed analysis, the caption index, and an options object carrying the tolerance, and returns a structured report containing the checked timestamp, the tolerance used, per-collection totals, the exact and normalized counts, and an array of violations where each violation carries kind, id, anchor t, quote, reason, and any matched segment start.

    Reuse the shipped Zod schemas from server/src/lib/analysis.ts and server/src/lib/models.ts to parse the inputs rather than redeclaring shapes, so a future schema change surfaces here as a type error instead of a silent miss. Keep the module free of console output.

    Treat the normalized classification as a signal, not a pass: it means the model paraphrased whitespace or casing, which the report should surface rather than hide.
