<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local server -> zai provider API | The full lecture transcript and the deck's extracted text leave the machine on this call |
| YouTube captions -> analysis prompt | Untrusted remote text is fed into an LLM prompt |
| third-party PDF -> pdf-parse | Untrusted binary is parsed in-process by the shipped extractor |
| proof run -> operator's real data root | A misconfigured harness would write into live user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | server dataDir resolution | high | mitigate | The run protocol re-asserts the API-reported dataDir equals the proof data root before any mutating request, and halts otherwise |
| T-04-02 | Information Disclosure | transcript and slide text sent to the third-party provider | medium | accept | This is the shipped design and the prior proof's own behaviour; the content is a public lecture and a published deck with no personal data, and the report states which provider and model processed it |
| T-04-10 | Spoofing | provenance of the analysis output | high | mitigate | Assert the stored model against the configured provider model and check the payload for the fake client's synthetic text before any fidelity claim is made |
| T-04-03 | Tampering | pdf-parse on an untrusted deck | medium | mitigate | The deck is sha256-recorded from a named publisher in 04-01 and parsed by the same shipped path a real learner would use |
| T-04-11 | Denial of Service | provider latency or a partial analysis failure | low | mitigate | Status polling is logged with timestamps against a pre-computed expectation, and any retry is recorded rather than silently repeated |
| T-04-SC | Tampering | package installs | n/a | accept | No package-manager install occurs in this plan |
</threat_model>
