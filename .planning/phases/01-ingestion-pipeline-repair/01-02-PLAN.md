<objective>
Compute and persist the empty-page signal PIPE-02 needs. `emptyPageCount` does not exist
anywhere in the codebase today; `PdfParseSlideExtractor` already walks every page's text
and throws the emptiness information away. This plan captures it, validates it through the
existing Zod schema, and returns it on the upload response so the web tier (plan 01-03)
has something real to warn about.

Purpose: an image-only deck must stop attaching a silently-empty slides channel.
Output: `emptyPageCount` flowing extractor -> schema -> `slides.json` -> upload response,
proven against real PDFs parsed by the real extractor.

Scope note: OCR and any "is this page an image" classifier are explicitly out of scope —
`server/src/lib/slides.ts:4` records frame-capture/OCR as future work, and PIPE-02 asks for
a signal, not a fix.
</objective>
