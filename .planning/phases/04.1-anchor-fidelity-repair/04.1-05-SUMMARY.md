## Issues Encountered

- **Pre-existing stale/conflicting harness processes.** At task start, two separate proof-harness process trees were found bound (or attempting to bind) to ports 4620/4621: one launched via a bare `tsx` invocation at 16:54:52-05:00 (one second before this phase's final commit landed at 16:55:53-05:00), and one launched earlier via the root `npm run dev`/`concurrently` whose server child had already died (its `tsx watch` parent process was still alive but not listening on 4620, `EADDRINUSE`-shadowed by the first). Resolved by killing both (`kill`, not `kill -9`; no file or git operation) and starting one clean instance. No repo files were affected by this remediation.
- **`gstack browse upload` against the "Attach slides (PDF)" button ref failed** (`Error: Node is not an HTMLInputElement`) because the button dispatches a click on a separate, hidden `input[type=file]` rather than being one itself. Resolved by targeting `input[type=file]` directly via CSS selector — the same underlying DOM element and the same one-real-UI-action upload flow 04-03's own manifest entry already documents for this exact control, not a new workaround requiring a FINDINGS.md entry.
- **Background poll monitor for the analysis job didn't fire a notification** when the run completed (`analyze/status` transitioned to `done` at 22:16:55Z), requiring the orchestrator to flag completion externally. The underlying poll loop itself worked correctly (full timestamped log captured, `DONE at 2026-08-10T22:16:55Z` recorded) — this was a notification-delivery gap in how the background task's completion signal was wired, not a defect in the analysis run or its evidence capture. All Task 3 evidence (wall-clock, counts, telemetry) was captured and verified after the orchestrator's flag, from the same log files the background loop had already written.
