## The dedup rule (exact)

Walk time-sorted cues carrying an accumulated tail of already-emitted words (case-folded, whitespace-collapsed tokens for comparison; original casing/punctuation preserved for output). For each cue:

1. **Guard 1 (time-touch gate):** only consider stripping an overlap when the cue's time range touches or overlaps the previous cue's (`a.start <= b.end && b.start <= a.end`). A genuine rolling pair always satisfies this (near-identical/overlapping start times); disjoint cues in a clean transcript rarely do, and even when they touch at a single boundary point, guard 2's content check finds nothing to strip.
2. **Guard 2 (bounded suffix/prefix overlap):** find the longest suffix of the last 40 words of the accumulated tail that is also a prefix of the cue's own words; strip that many words off the front of the cue before emitting. Bounding the search to 40 words (not the whole transcript) caps cost and prevents a false match against unrelated content spoken minutes earlier (T-04.1-04).
3. Emit a segment with only the words beyond the overlap, timed at the cue's own start/end. A cue whose overlap covers its entire text (a pure "reset" cue) is dropped entirely.

Both guards are required together: guard 1 alone would misfire on any two touching-but-disjoint cues (correctly no-ops there because guard 2 finds zero overlap); guard 2 alone (no time gate) risks stripping a genuinely repeated phrase spoken far apart in time.

## The correction rule (exact — three outcomes)

For each unit anchor, `correctAnalysisAnchors` calls the shared `findQuoteOccurrences` (exact-substring occurrences, falling back to whitespace/case-normalized substring occurrences):

1. **Quote not found anywhere** → left untouched (same object reference), recorded in `unresolved` — a timestamp is never invented for an unlocatable quote.
2. **Some occurrence starts within tolerance (default 15s, `anchorVerify.ts`'s `DEFAULT_TOLERANCE_SEC`) of the claimed `t`** → left untouched (same object reference) — the pass never "improves" an anchor the verifier would already accept.
3. **Otherwise** → `t` is set to `Math.min(...occurrences.starts)` (the earliest occurrence, D-01 item 2's "earliest teaching-pass" rule), recorded as a correction with the unit's id, type, before/after values. A new anchor object is returned but reuses the original `quote` string reference unchanged.

## Decisions Made

- `correctAnalysisAnchors<T extends { units?: readonly AnalysisUnit[] }>` is generic over the minimal `{ units }` shape rather than requiring the full `Analysis` type, because `runAnalysisJobV3` calls it on the intermediate post-merge snapshot before pearls/edges/themes exist. Both the wiring site and Task 2's direct-unit-test fixtures use this same minimal shape.
- Earliest-occurrence selection uses `Math.min(...occurrences.starts)` rather than assuming `findQuoteOccurrences`'s left-to-right document-order result already equals chronological order — correct regardless of whether a caller's segment array happens to be time-sorted.
- The corrector's tolerance defaults to `anchorVerify.ts`'s own `DEFAULT_TOLERANCE_SEC` (15s) rather than a locally-redeclared constant, so the corrector and the verifier can never silently drift apart on what "within tolerance" means.
